## User outcome

After connecting accounts, Mailboxes keeps global All Mail and lists every configured
account beneath it. Each account has a photo on the left and a disclosure control.
Expanding an account reveals its mailbox views; selecting a view displays only matching
messages from that account. Multiple accounts can remain expanded.

```text
Mailboxes
  All Mail
  [photo] personal@example.com       v
      Inbox
      Starred
      Snoozed
      Spam
      Archive
      Trash
      Other folders                  >
  [photo] work@example.org           >
```

The addresses above are synthetic. Actual account metadata exists only at runtime.

## Proposed behavior for approval

- All Mail remains the global default and includes all locally indexed messages across
  accounts, preserving its existing behavior. It must not silently acquire exclusions
  for spam, trash, or snoozed messages. Inbox excludes active snoozes; explicit folder
  views remain inspectable. The reader indicates active snoozes where applicable.
- The account header toggles expansion without changing the current mailbox selection.
  A child item selects an account-scoped view. The toolbar identifies that account and view.
- Show Inbox, Starred, and Snoozed for every account. Show special server folders when
  discovered; group remaining selectable folders under Other folders. No fake empty folders.
  Sent and Drafts, when present, are read-only views; no composition or SMTP is added.
- Inbox is a real server folder. Spam, Archive, and Trash resolve to actual server paths,
  preferring advertised roles and using existing provider fallbacks cautiously.
- Starred is a virtual view of persisted IMAP `\Flagged`, with explicit star/unstar actions
  and durable two-way flag synchronization. It is not a guessed folder called Starred.
- Snoozed is local application metadata with a persisted UTC deadline and explicit
  snooze/unsnooze actions. Expiration returns the message to Inbox eligibility without
  moving it or marking it unread. Reconcile on startup, resume, and while running.
  Provider-native snooze synchronization is excluded.
- Photos are selected from local raster files, bounded and normalized by native code,
  and stored inside encrypted application storage. Use deterministic initials/color when
  no image exists. Support replace/remove from account management. No Gravatar, OAuth
  profile requests, remote image URLs, or email-derived external lookups.
- Persist expansion preferences locally by opaque account ID, without duplicating email
  addresses, photos, credentials, or message content into browser localStorage.
- Search, load-more, refresh, and triage operate within the selected scope. Scope changes
  reset selection, reader, scroll, and pagination; late responses cannot cross scopes.
- Distinguish loading, no messages, not yet synced, unavailable folder, and offline/error.
  Cached messages and folder metadata remain usable offline. Omit mailbox count badges
  initially; existing list counts describe loaded results, not authoritative totals.
- Keyboard-accessible disclosure buttons use `aria-expanded`; mailbox selection has a
  distinct active indicator. Support existing responsive shell, reduced motion, and EN/PT-BR.

## Repository findings and constraints

- `Sidebar.svelte` currently renders one static All Mail link.
- `DesktopApp.svelte` owns the account controller but does not pass its account list into
  `InboxSession` / `InboxView` / `Sidebar`.
- Storage `HybridQuery.account_filter` exists. IPC `SearchQueryDto` does not expose it
  and currently sets it to `None`; frontend-only filtering would break complete pagination.
- Worker sync revisits checkpointed folders plus INBOX. General folder discovery is
  missing; its IDLE checkpoint is currently INBOX-based. Do not create one idle socket
  per folder. Plan bounded polling for other folders and prioritize the selected folder.
- Existing role classification and archive/trash LIST handling can be reused, but the
  latter is a restricted mutation helper, not a complete mailbox catalog parser.
- Persisted messages currently expose read state, not a starred field or snooze deadline.
- P1 requires backward-compatible IPC additions and append-only migrations from released
  schema v1. Preserve existing commands, enum representations, trait signatures, and
  canonical message/account/folder/UID identity used by lazy attachments and mutations.
- Domain services remain pure Rust. Extend functionality through separate types/helpers
  or extension traits; any necessary breaking contract requires a revised approved plan.
- Existing unrelated edits in onboarding and translation files must be preserved.
